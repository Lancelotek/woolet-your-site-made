- Kickstarter signup's paid decision view renders in a body portal so it can occupy the screen independently of any of the three signup locations; the existing checkout button owns the session and tracking to avoid duplicate events.
- Redirects live only as data in src/seo/legacyRedirects.ts + src/seo/routeRedirects.ts (no new <Navigate> routes); router and prerender stubs both consume them, and scripts/audit-routes.mjs fails the build when an App.tsx path would serve the noindex fallback ; each source is emitted as a minimal noindex,follow stub (meta refresh + canonical to target, no copied content) — Google never sees client-side redirects or soft-404 duplicates. /en/collections/* crawler text comes from src/seo/collection-snapshots.json (refresh via scripts/snapshot-collections.py) so prerender matches the hydrated page.
- hreflang comes only from src/i18n/routeRegistry.ts (prerender head, Helmet via seo/hreflangLinks, sitemap); the registry drops non-reciprocal clusters and generate-sitemap fails the build on any one-way pair — Google ignores non-reciprocal annotations.
- Blog posts may opt into exactContent to suppress automatic waitlist insertions, and an author override feeds static Article schema; this preserves approved editorial copy and bylines across rendering paths.
- Prerendered blog month placeholders resolve from the rendered route's slug and are validated before route writes; unresolved blogModifiedMonthLabel values must exit non-zero to prevent incomplete crawler bylines.
- Prerendered head tags are removed only after Helmet writes equivalents (src/lib/strip-prerender-seo.ts MutationObserver) — avoids an empty head on lazy routes.

- Image derivatives are indexed in src/data/optimized-images.json and selected through src/lib/optimized-image.ts; CDN pointers preserve originals for zoom while thumbnails and responsive galleries use smaller WebP files.
- Stripe.js is dynamically imported by getStripe; reservation buttons mount only in the payment step and create sessions only on a visitor tap, preserving checkout attribution.
- Route image preloads are emitted by scripts/prerender.mjs and matching Helmet tags; the shared SPA shell never preloads a route-specific hero.
- Self-hosted fonts used by the app live in src/assets/fonts and are referenced relatively from CSS and index.html so Vite fingerprints them without host-header dependencies; legacy public copies remain compatible.

- FitScan initializes its mobile breakpoint before first paint and reserves panel height; other consumers of useIsMobile retain the existing initialization behavior.
- Register public pages in src/seo/metadata.ts and utility/conversion pages in src/seo/app-page-metadata.ts; SEO reads the shared utility metadata by current pathname so prerender and navigation agree, and audit-routes requires real titles/descriptions even for noindex pages to prevent 404-shell leakage.
- Our story uses one shared editorial HTML/photo source for React and crawler content, preventing approved copy from drifting; its typography is page-scoped to avoid restyling existing pages.
- The runtime Woolet Organization schema uses src/content/organization.json, mirrored in index.html for crawlers; AboutPage nodes reference its stable identity rather than duplicating facts.
- Bespoke AI renders are generated once per canonical v2 selection key (server-built, includes lens + tint) and served from the public bespoke_render_cache table + bespoke-renders bucket; clients never receive base64 — this stops repeat AI spend and lets every visitor reuse a render.
- Configurator pattern examples use one query for explicit featured selection keys, never popularity; exact-config lookups remain independent so examples never pollute saved preview history.
- Bespoke angle regeneration is admin-validated server-side and sequential/user-initiated; upload new immutable paths before replacing cache records so failures and existing order URLs remain safe.
- Bespoke render inputs put the geometry drawing first; only Round receives a composition photo last, while non-round shapes use text-only camera rules (Aviator retains construction photos) to prevent photo geometry leakage.
- Configurator price breakdowns derive from computePricing without step gating, so restored add-ons remain visible and totals match every surface.
- The edge Worker's known-route set is generated only from src/seo/routeCatalog.ts (App.tsx routes + prerender catalog + slug data) by workers/route-server/build-bundle.mjs, which fails the deploy on any uncovered route; the Worker passes everything through and only flips unknown documents to 404 — no hand-maintained route lists, no embedded HTML.
